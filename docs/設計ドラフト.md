# みらい議会 -遠賀町版- 設計ドラフト v0.2

最終更新: 2026-09-22

---

## 1. 目的

1. 遠賀町議会の議事を、町民がわかりやすく把握できるようにする。
2. 各議員と町（町長・執行部）のやりとり、特に**誰がどんな発言をしたか**がすぐにわかるようにする。
3. 議案ごとに、質疑・討論・議決結果をひとつのページで追えるようにする。

## 2. 決定事項

| 項目 | 決定内容 |
|---|---|
| 構成 | プランB：静的サイト＋データ生成パイプライン |
| ホスティング | エックスサーバー（静的ファイルのみ） |
| URL | `miraigikai.onga-mirai-tech.<TLD>`（サブドメイン、無料SSL） |
| 立場 | 個人の非公式サイト |
| 対象期間 | 平成17年〜の原文をすべて収集。**公開は令和元年〜を先行**し、平成分は順次追加 |
| 議案 | 扱う |
| AIチャット | 実装しない |
| AI要約 | Claude API（Batch API）でビルド時に生成・保存 |
| 議員の顔写真 | 扱わない |
| 更新頻度 | GitHub Actions で**毎月1回**確認（手動実行も可） |
| 公開フロー | 半自動（PR作成 → プレビュー確認 → マージで本番反映） |

## 3. 全体構成

```
[VOICES 会議録システム] ──(月1回・低頻度取得)──▶ [GitHub Actions]
                                                   │
      ① 取得 fetch        data/raw/        原文HTMLを保存
      ② 整形 parse        data/normalized/ 会議・発言・議案をJSON化
      ③ 要約 summarize    data/summaries/  Claude Batch API
      ④ 検証 verify       数字・固有名詞の照合、スキーマ検証
      ⑤ 生成 build        dist/            静的HTML・検索インデックス
                                                   │
                         PR作成 ─▶ プレビュー確認 ─▶ マージ
                                                   │
                                        SFTP ─▶ [エックスサーバー]
```

## 4. データソース

### 4-1. 会議録（VOICES）

- トップ: `http://iasb-sv.town.onga.lg.jp/voices/index.asp`
- 年度・種別ごとの一覧は `index.asp?Sflg=11&FYY=YYYY&TYY=YYYY`（定例会）、`Sflg=21`（臨時会）。
- 一覧本体は `cgi/voiweb.exe?ACT=100&...` をフレーム内で表示する構成。
- 収録範囲: 平成17年（2005）〜 令和8年（2026）の定例会・臨時会。
- **P0で確認すること**
  - 文字コード（Shift_JIS の可能性が高い）
  - 会議録本文ページのURL規則と、1日分・1会議分の単位
  - 発言者の表記ルール（例：「○議長（氏名君）」「○○番（氏名君）」「○町長（氏名君）」など）
  - 発言区切りの記号、ト書き（「〔拍手〕」「起立多数」など）の表記
  - 目次・出席者一覧・議事日程の位置と形式
  - 委員会の会議録が含まれるか
  - 平成17年頃と令和の会議録で形式に差があるか
  - https 対応の有無（http のみならパイプライン側で取得するだけなので問題なし）

### 4-2. 議案・議決結果

- 会議録内の「議案第○号」の上程・質疑・討論・採決の流れから抽出する。
- 町HPの議会ページ（議決結果・議会だより）に一覧があるかを P0 で確認する。PDFの場合は解析工程を追加する。
- 採決は起立採決が多く、会議録には「起立多数」等しか残らないことが一般的。**個人別賛否は公表資料にある場合のみ扱う。**

### 4-3. 議員情報

- 氏名・会派・在任期間を町HP等の公開情報から手動で `data/masters/` に登録する。
- 顔写真は扱わない。

## 5. データモデル

IDは読みやすく安定したものにする。

### Meeting（会議）
```json
{
  "id": "2025-t3",
  "type": "定例会",            // 定例会 | 臨時会
  "year": 2025,
  "era_label": "令和7年",
  "number": 3,
  "title": "令和7年第3回定例会",
  "days": [
    { "day": 1, "date": "2025-09-02", "source_url": "http://iasb-sv..." }
  ],
  "agenda": ["開会", "議案上程", "一般質問", "..."]
}
```

### Speaker（発言者）
```json
{
  "id": "sp-yamada-taro",
  "name": "山田 太郎",
  "kind": "議員",               // 議員 | 町長 | 副町長 | 教育長 | 執行部 | 議長 | その他
  "roles": [
    { "title": "議員", "faction": "〇〇会", "from": "2019-05-01", "to": null }
  ],
  "aliases": ["山田太郎君", "山田議員"]
}
```
- 執行部（課長など）は年度で役職が変わるため、`roles` に履歴を持つ。
- 表記ゆれは `aliases` で吸収する。自動判定できなかったものは一覧に出して手動で登録する。

### Utterance（発言）
```json
{
  "id": "2025-t3-d2-0045",
  "meeting_id": "2025-t3",
  "day": 2,
  "seq": 45,
  "speaker_id": "sp-yamada-taro",
  "role_at_time": "議員",
  "text": "（原文）",
  "section": "一般質問",        // 議事の区分
  "thread_id": "2025-t3-q05",   // 一般質問の場合
  "bill_ids": [],               // 議案の質疑・討論の場合
  "source_url": "http://iasb-sv..."
}
```

### Thread（一般質問のやりとり）★中核
```json
{
  "id": "2025-t3-q05",
  "meeting_id": "2025-t3",
  "questioner_id": "sp-yamada-taro",
  "topics": ["通学路の安全対策について"],
  "responders": ["sp-choucho", "sp-kyouikuchou"],
  "utterance_ids": ["2025-t3-d2-0045", "..."],
  "tags": ["教育", "防災"]
}
```
- 1人の議員の一般質問を1スレッドとし、通告テーマが複数ある場合は `topics` に並べる。
- 画面では「質問 → 答弁 → 再質問 → 再答弁…」の往復として表示する。

### Bill（議案）
```json
{
  "id": "2025-t3-b12",
  "meeting_id": "2025-t3",
  "number": "議案第12号",
  "title": "遠賀町〇〇条例の一部を改正する条例の制定について",
  "category": "条例",           // 条例 | 予算 | 決算 | 人事 | 契約 | 意見書 | 請願 | 報告 | その他
  "proposer": "町長",
  "submitted_on": "2025-09-02",
  "decided_on": "2025-09-19",
  "result": "原案可決",
  "vote_note": "起立多数",       // 会議録の記載そのまま
  "individual_votes": null,      // 公表資料がある場合のみ
  "utterance_ids": []            // 質疑・討論の発言
}
```

### Summary（AI要約）
```json
{
  "target_type": "thread",       // meeting | thread | bill | utterance
  "target_id": "2025-t3-q05",
  "summary": "（要約本文）",
  "points": [
    { "who": "sp-yamada-taro", "text": "（質問の要点）", "utterance_id": "..." },
    { "who": "sp-choucho", "text": "（答弁の要点）", "utterance_id": "..." }
  ],
  "model": "claude-...",
  "prompt_version": "thread-v1",
  "generated_at": "2026-10-01T02:00:00+09:00",
  "verified": true
}
```
- `points` の各要点は必ず元の発言IDに紐付け、画面から原文へ飛べるようにする。

## 6. 画面構成とURL

| URL | 画面 | 内容 |
|---|---|---|
| `/` | トップ | 最新の定例会サマリ、主な一般質問、最近の議案 |
| `/meetings/` | 会議一覧 | 年度・種別で絞り込み |
| `/meetings/{id}/` | 会議ページ | 議事の流れをタイムライン表示、一般質問・議案への導線 |
| `/questions/{id}/` | 一般質問ページ ★ | チャット風UI（議員は左、町側は右）。各発言に「要約／原文」切替と原典リンク |
| `/bills/` | 議案一覧 | 種別・結果・年度で絞り込み |
| `/bills/{id}/` | 議案ページ | 概要、質疑・討論の発言、議決結果 |
| `/members/` | 議員一覧 | 現職・元職 |
| `/members/{id}/` | 議員ページ | 質問したテーマ一覧、年度別の質問回数、関連議案での発言 |
| `/topics/{tag}/` | テーマ別 | 子育て・防災・財政・教育などのテーマ横断 |
| `/search/` | 検索 | キーワード・発言者・年度・テーマで絞り込み |
| `/about/` | このサイトについて | 非公式である旨、データ出典、AI要約の方針、免責、問い合わせ |

### 表示ルール
- AI要約には「AI要約」ラベルを付け、原文リンクを必ず併記する。
- 数値の並べ方は事実の提示にとどめ、ランキング表示や多い／少ないの評価はしない。
- 各ページにOGP（タイトル・説明）を設定する。OGP画像は共通画像1枚から始める。
- フッターに非公式・AI要約・原典参照の注記を常時表示する。

### 検索
- ビルド時に年度別の検索インデックス（JSON）を生成し、ブラウザ側で読み込んで検索する。
- 日本語は単語区切りが難しいため、まずは文字n-gram（2-gram）方式で実装する。
- 外部の検索サービスやCDNは使わない。

## 7. AI要約の方針

### 使い方
- Claude API の **Batch API** で一括処理する（50%割引、即時性不要）。
- 生成済みの要約は再生成しない。プロンプト変更時のみ明示的に再生成する。
- モデルは、まず軽量モデルと中位モデルで数件ずつ試し、品質と費用を比べて決める（P4）。

### 費用の考え方
- 従量課金。閲覧数には比例せず、**要約を生成するときだけ**費用が発生する。
- 初回一括（令和元年〜）は一度きり。定例会ごとの追加分は小さい見込み。
- 正確な見積もりは P0 で会議録の分量を測ってから算出する。
- Anthropic のコンソールで利用上限額を設定しておく。

### プロンプトの原則
- 発言者が言っていないことを補わない。推測・評価・感想を書かない。
- 数字・日付・固有名詞は原文どおりに書く。
- 答弁は「何をする／しない／検討する」という結論を明確にする。
- 要点ごとに根拠となる発言IDを出力させる（JSON形式）。

### 検証（verify）
- 要約中の数字・金額・日付・固有名詞が、紐付いた原文に含まれているかを機械的にチェックする。
- 不一致があれば `verified: false` にして PR 上で一覧表示し、人が確認する。

## 8. 更新・公開フロー

### 月次更新（monthly-update.yml）
- 実行: **毎月1日 日本時間の深夜**（cron は UTC 表記のため時差に注意）＋手動実行（workflow_dispatch）。
- 処理:
  1. VOICES の一覧を確認し、未取得の会議録があれば取得する。
  2. 整形 → 要約（Batch API、完了まで待機）→ 検証 → ビルド。
  3. プレビュー用にエックスサーバーの `preview` 領域（Basic認証付き）へデプロイする。
  4. 変更内容と検証結果をまとめた **Pull Request** を作成する。
- 新しい会議録がない月も `data/state.json` の最終確認日時を更新してコミットする。
  - GitHub は60日間更新のないリポジトリの定期実行を自動停止するため、その対策。

### 本番デプロイ（deploy.yml）
- main へのマージをきっかけに、ビルドして SFTP でエックスサーバーの公開ディレクトリへ反映する。

### Secrets
| 名前 | 用途 |
|---|---|
| `ANTHROPIC_API_KEY` | AI要約 |
| `XSERVER_HOST` / `XSERVER_USER` / `XSERVER_SSH_KEY` | SFTPデプロイ |
| `XSERVER_PUBLIC_DIR` / `XSERVER_PREVIEW_DIR` | デプロイ先 |

## 9. 開発フェーズ

| フェーズ | 内容 | 完了条件 |
|---|---|---|
| **P0 構造調査** | 会議録（令和・平成それぞれ1日分）と議案資料の所在を調査 | `docs/調査報告_P0.md` に形式・URL規則・発言者表記・分量の見積もりをまとめる |
| **P1 収集** | 平成17年〜の会議録原文を全件取得 | `data/raw/` に全件保存、再実行時に取得済みをスキップできる |
| **P2 整形** | 令和元年〜の発言分割、発言者マスタ、一般質問スレッド化、議案抽出 | 未判定の発言者が一覧で確認でき、手動マスタで解消できる |
| **P3 閲覧MVP** | 一般質問・会議・議案ページ（原文のみ、AIなし） | スマホで一般質問のやりとりが読める状態でプレビュー公開 |
| **P4 AI要約** | スレッド・議案・会議の要約と検証 | 要約に原文リンクが付き、検証結果がPRに出る |
| **P5 議員ページ・検索・公開** | 議員・テーマ・検索・about、月次ワークフロー、本番公開 | 独自ドメインで公開、月次PRが自動で作られる |
| **P6 平成分の追加** | 平成17年〜30年を年度単位で順次整形・要約 | 年度ごとにPRで追加 |
