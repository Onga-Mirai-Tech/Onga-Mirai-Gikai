# P0 構造調査 手順書

このファイルは **調査のやり方** を定めたもの。調査の **結果** は `docs/調査報告_P0.md` に書く。

---

## 0. 前提：取得マナー（CLAUDE.md より）

P0 の調査でも例外なく守る。

- **1リクエストごとに3秒以上あける。並列アクセスはしない。**
- 取得した原文HTMLは `data/raw/_p0/` に保存し、**同じURLを二度取りに行かない**。
- User-Agent に連絡先（このリポジトリのURL）を含める。
- 相手は町のサーバー。**調査全体で10リクエスト程度に収める**。当たりをつけずに総当たりしない。

### 「深夜帯に実行」について
CLAUDE.md の「実行は日本時間の深夜帯」は、**P1以降の一括取得を想定したルール**。
P0 は合計10件程度の探索なので日中に実行してよい、と判断する。
ただし件数が増えそうなら深夜帯に回すこと。

### 取得コマンドの雛形

```bash
# 使い方: fetch_p0 <URL> <保存名>
fetch_p0() {
  url="$1"; out="data/raw/_p0/$2"
  if [ -f "$out" ]; then echo "skip (取得済み): $out"; return; fi
  mkdir -p data/raw/_p0
  curl -sS -D "$out.headers" -A \
    'onga-mirai-gikai-bot/0.1 (+https://github.com/Onga-Mirai-Tech/Onga-Mirai-Gikai)' \
    -o "$out" "$url"
  sleep 3
  echo "saved: $out"
}
```

保存したら必ずレスポンスヘッダ（`*.headers`）も残す。文字コードの判定に使う。

## 1. 文字コードとページ構成を調べる

対象: `http://iasb-sv.town.onga.lg.jp/voices/index.asp`

1. 上記で取得する。
2. 文字コードを3か所で確認し、`調査報告_P0.md` に記録する。
   - レスポンスヘッダの `Content-Type: ...; charset=`
   - HTML内の `<meta http-equiv="Content-Type">` / `<meta charset>`
   - 実バイト列からの推定（`file -I`、`nkf --guess`、または Python の `chardet` 相当）
   - **3つが食い違う場合は実バイト列を信じる**。宣言と実体がズレている古いASPサイトは珍しくない。
3. フレーム構成を確認する（`<frameset>` / `<iframe>` の `src`）。一覧の本体がどのURLにあるかを特定する。
4. https でも配信されているか確認する（`https://` で1回だけ試す）。

読むときの注意: Shift_JIS のファイルをそのまま `cat` しても化ける。
`iconv -f CP932 -t UTF-8` を通してから読む（`SHIFT_JIS` ではなく **`CP932`** を指定すること。機種依存文字で落ちるため）。

## 2. 一覧URLの規則を調べる

設計ドラフト 4-1 に書かれている想定を、実物で確かめる。

- 定例会: `index.asp?Sflg=11&FYY=YYYY&TYY=YYYY`
- 臨時会: `index.asp?Sflg=21&...`
- 本体: `cgi/voiweb.exe?ACT=100&...`

確認すること:

- `Sflg` / `FYY` / `TYY` / `ACT` それぞれが何を意味するか
- 年度の指定方法（西暦か和暦か、年度か暦年か）
- 会議録本文ページへのリンクがどう組み立てられているか（クエリのどのパラメータが会議・日・発言を指すか）
- **GET だけで到達できるか**。POST や セッションID（Cookie）が必要な場合、取得パイプラインの作りが変わるので必ず記録する。

令和7年度の定例会一覧を1件だけ取得して確かめる。

---

## 3. 会議録本文（令和・1日分）を調べる

一覧から1日分を選んで取得し、以下を実物の抜粋つきで記録する。

- **1ページの単位**（1日分まるごとか、発言ごとか、ページ送りがあるか）
- **発言者の表記ルール**（例:「○議長（氏名君）」「○○番（氏名君）」「○町長（氏名君）」）
  - 行頭記号は `○` か `◯` か全角丸か。**実際のコードポイントを控える**（正規表現を書くときに効く）
  - 氏名のあとの敬称（「君」「さん」）
  - 議席番号つきの表記と役職名の表記が混在するか
- **発言の区切り**（改行のみか、空行か、記号か）
- **ト書き**の表記（`〔拍手〕` `〔起立多数〕` など、括弧の種類も含めて）
- **目次 / 出席者一覧 / 議事日程** の位置と形式（本文と同じページか、別ページか）
- **一般質問の始まりと終わりを機械的に判定できるか**（「日程第○ 一般質問」のような見出しがあるか）
- **議案の上程・質疑・討論・採決**がどう書かれているか（「議案第○号」の表記ゆれ、採決結果の書き方）

ここが P2（整形）の実装難易度を決める。抜粋は多めに `調査報告_P0.md` に貼る。

## 4. 会議録本文（平成・1日分）を調べる

平成17〜19年ごろから1日分を取得し、**3. と同じ項目**を確認して差分だけ記録する。

特に見るところ:

- 発言者表記が変わっていないか
- 文字コードが変わっていないか（古い分だけ別エンコードのことがある）
- HTMLの構造（table主体 / pre主体 など）が違わないか

差が大きければ、P2 のパーサを年代で分岐させる必要がある。**P6（平成分の追加）の工数見積もりに直結する。**

---

## 5. 委員会会議録の有無

一覧に常任委員会・特別委員会の会議録が含まれるかを確認する。
含まれる場合、対象に入れるかは**設計判断なので、判断せず「含まれる」事実だけ記録して相談する**。

---

## 6. 議案・議決結果の所在

遠賀町公式サイトの議会ページを確認する（VOICESとは別ドメイン。**こちらも間隔を空ける**）。

- 議決結果の一覧があるか。形式は HTML か PDF か
- 議会だよりのPDFに議案一覧が載っているか
- **個人別の賛否が公表されているか**
  - CLAUDE.md の絶対ルール: 公表資料に明記がある場合のみ扱う。なければ「なし」と記録して終わり。推測しない。

PDFしかない場合は、解析工程が1つ増える。見積もりに反映する。

---

## 7. 分量とコストの見積もり

3. で取得した1日分から概算する。**新たな取得はしない。**

1. 1日分の本文文字数を数える（HTMLタグを除いた文字数）
2. 令和元年〜現在の会議数 × 平均日数 を一覧ページから数える
3. 平成17年〜も同様に数える
4. 総文字数を出す
5. トークン数を概算する（日本語はおおむね 1文字 ≒ 1トークン弱で見積もると安全側）
6. Claude Batch API での費用を概算する
   - モデルは P4 で比較して決めるため、**軽量モデルと中位モデルの2通りで出す**
   - 最新の料金は思い出しで書かず、その時点の公式価格を確認して書く
   - Batch API は50%割引

出力は「令和元年〜（初回一括）」「平成17年〜（P6）」「定例会1回あたりの追加分」の3つに分けて出す。

## 8. まとめ

`docs/調査報告_P0.md` の表をすべて埋め、最後の「判断メモ」に次を書く。

- P2 のパーサ実装で難所になりそうなところ
- 設計ドラフトの想定と実物が食い違った点
- 相談が必要になった設計判断（委員会の扱い、依存ライブラリ、モデル選定など）

未調査のまま残った項目は、**空欄にせず「未調査」と理由を書く**。

## P0 完了の条件

- `docs/調査報告_P0.md` の表に「未調査」が残っていない
- `data/raw/_p0/` に根拠のHTMLが保存されている
- 費用の概算が出ている
