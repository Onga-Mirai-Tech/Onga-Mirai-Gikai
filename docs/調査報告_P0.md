## 1. VOICES の基本

| 項目 | 結果 | 備考 |
|---|---|---|
| 文字コード | **CP932（Shift_JIS）** | 3か所とも矛盾なし。下の「文字コードの確認」参照 |
| https 対応 | **非対応（http のみ）** | `https://iasb-sv.town.onga.lg.jp/` は15秒でタイムアウト。取得は http で行う |
| 一覧URLの規則 | `index.asp` は**ガワだけ**。実体は iframe 内の `cgi/voiweb.exe?ACT=100...` | 下の「URL規則」参照 |
| 本文ページのURL規則 | `cgi/voiweb.exe?ACT=203&FINO=<日程ID>&HATSUGENMODE=1&HYOUJIMODE=0&STYLE=0` | **これ1本で1日分の全文が取れる** |
| 1ページの単位 | **1日分（1日程）まるごと。ページ送りなし** | 374発言・111KBの日も1レスポンスで完結（`06_honbun_r08_0609_03_ACT203.html`） |
| 収録範囲 | **平成17年（2005）〜 令和8年（2026）**。定例会・臨時会の**本会議のみ** | 定例会 375日程。臨時会は約85日程と推定（4.参照） |
| 委員会会議録の有無 | **なし**。VOICESは本会議だけを収録している | 詳細検索の「会議の種類」は定例会/臨時会の2つのみ（`09_search_form.html`） |

### 文字コードの確認

| 確認方法 | 結果 |
|---|---|
| レスポンスヘッダ | `Content-Type: text/html`（**charset の指定なし**） |
| HTML内の meta | `index.asp` → `charset=shift_jis` / 一覧・本文（voiweb.exe） → `charset=Shift_JIS` / ACT=200のフレームセット → `charset=x-sjis` |
| 実バイト列 | **CP932 で正常にデコードできる** |

- 宣言と実体は食い違っていない。ただし `x-sjis` という非標準の表記が混ざるので、**宣言は読まずCP932決め打ちでデコードする**のが安全。
- **`SHIFT_JIS` ではなく `CP932` を使うこと。** 令和8年6月8日の本文に「﨑山栄子」（﨑 = U+FA11、NEC/IBM拡張）が出現しており、`SHIFT_JIS` 指定ではデコードに失敗する。

### URL規則（すべて GET で到達可能。Cookie 不要）

`index.asp` は ASP セッション Cookie（`ASPSESSIONID...`）を発行するが、**`cgi/voiweb.exe` は Cookie を送らなくても正常に応答する**。POST も不要。取得パイプラインは素の GET だけで組める。

| パラメータ | 意味 | 値 |
|---|---|---|
| `ACT` | 画面の種類 | `100`=会議日程一覧 / `200`=本文フレームセット / `201`=ヘッダ / `202`=サイドバー（目次） / `203`=**本文テキスト** / `204`=サイドバー見出し |
| `KGTP` | 会議種別 | `1`=定例会 / `2`=臨時会（この2つのみ。委員会はない） |
| `KTYP` | **発言者区分**（会議種別ではない） | `1`=議長・委員長 / `2`=質問者 / `3`=答弁者 / `0`=目次・その他 |
| `YEAR` / `FYY` / `TYY` | 年 | **西暦の暦年**（年度ではない）。例: `YEAR=2019` は「令和01年」として扱われる |
| `KGNO` | 会議番号（通し番号） | 例: `167`=令和8年第3回定例会、`15`=平成18年第6回定例会 |
| `FINO` | **日程ID（通し番号）。1日分を一意に指す主キー** | 例: `458`=令和8年6月8日-02号、`31`=平成18年6月16日-03号 |
| `UNID` | 日程の文字列ID | `K_` + 元号記号 + 年2桁 + 月2桁 + 日2桁 + 号4桁 + `1`。例: `K_R08060800021`（令和8年6月8日-02号） |
| `TITL_SUBT` | 画面表示用のタイトル（Shift_JISのURLエンコード） | **省略可**。取得には不要 |

実際に使うURLは3つだけ:

```
# 年の一覧（その年の全日程＋FINO/UNIDが取れる）
http://iasb-sv.town.onga.lg.jp/voices/cgi/voiweb.exe?ACT=100&KENSAKU=0&SORT=0&KTYP=0,1,2,3&KGTP=1&YEAR=2026

# 全期間の一覧（ヒット件数が取れる。KGTP=1:定例会 / 2:臨時会）
http://iasb-sv.town.onga.lg.jp/voices/cgi/voiweb.exe?ACT=100&KTYP=0,1,2,3&SORT=0&FYY=&FMM=&TYY=&TMM=&KGTP=1

# 本文（1日分の全文）
http://iasb-sv.town.onga.lg.jp/voices/cgi/voiweb.exe?ACT=203&FINO=458&HATSUGENMODE=1&HYOUJIMODE=0&STYLE=0
```

**`index.asp?Sflg=11&FYY=YYYY&TYY=YYYY` という設計ドラフトの想定は、ガワのHTMLに到達するだけで中身がない。**
`Sflg` は index.asp 側の画面切替（10=定例会すべて / 11=定例会・年指定 / 20=臨時会すべて / 21=臨時会・年指定）で、パイプラインでは使わなくてよい。

## 2. 本文の書式

| 項目 | 結果 |
|---|---|
| 発言者の表記ルール | 行頭1文字の記号 + 肩書 + `（氏名）`。**敬称なし・氏名に空白なし**。`○議長（織田隆徳）` / `◆３番議員（田代順二）` / `◎税務課長（井口正彦）` |
| 行頭記号のコードポイント | `○` **U+25CB**（議長・委員長）/ `◆` **U+25C6**（質問者＝議員）/ `◎` **U+25CE**（答弁者＝町長・課長等）/ `△` **U+25B3**（日程見出し）。KTYP の 1/2/3 と一対一で対応する |
| 発言の区切り記号 | `<P>` タグ + `<A NAME="HUID<発言ID>"></A>`。**HUIDは全会議を通した発言の通し番号** |
| 改行 | `<BR>`。段落先頭は全角スペース1つ |
| ト書きの表記 | **`───　○○　───`**（U+2500 ×3 + 全角スペース）。例: `───　開議　午前９時30分　───` / `───　質疑なし　───` / `───　異議なしの声　───` / `───　賛成者起立　───` / `───　休憩　午前９時39分　～　再開　午前９時41分　───` |
| 目次の位置と形式 | 本文と**別ページ**（`ACT=202`）。ただし本文ページ（ACT=203）の先頭に議事日程が入るため、**目次ページは取らなくてよい** |
| 出席者一覧の位置と形式 | **本文ページ（ACT=203）の先頭**。`１．議長の氏名` `２．説明のため出席した者の氏名・職` `３．書記の氏名` `４．議員の出欠` の4節。議員の出欠は罫線素片（`┌─┬─┐`）で組んだアスキーアート表で、`／`=出席 / `△`=欠席 |
| 議事日程の位置と形式 | 同じく本文ページの先頭、出席者一覧の直後。`日程第１　　議案第４１号　　…` の形式で、右端に `〔議案質疑・委員会付託・討論・採決〕` のように取扱いが付く |
| 平成17年頃と令和での形式差 | **ほぼ差がない。パーサの年代分岐は不要**（下記） |

| 項目 | 平成18年（`08_honbun_h18_0616_03_ACT203.html`） | 令和8年（`05`/`06`） | 影響 |
|---|---|---|---|

**設計ドラフトの「○議長（氏名君）」という想定は誤り。** ラベルに「君」「さん」は付かない。「君」は平成期の議長の**発言本文の中**にだけ出る。

### 一般質問の判定

機械的に判定できる。

- 開始: `△日程第２　これより、通告順に従い、一般質問を許します。２番議員、野口久美子議員。`
- 各議員の終了: `以上で、野口久美子議員の一般質問は終了致しました。`（議員ごとに1回、必ず出る）
- 議事日程の見出しは `日程第２　　一　般　質　問` と**1文字ずつ全角スペースで区切られている**ため、`一般質問` の単純一致では拾えない。空白を除去してから照合すること。

### 日程見出しの表記ゆれ（注意）

- 議事日程（ページ先頭の一覧）… `日程第10`（**半角算用数字**）
- 本文中の見出し … `△日程第１０`（**全角算用数字**）

同じ日の中で表記が違う。突き合わせるときは正規化が要る。

## 3. 議案・議決結果

| 項目 | 結果 |
|---|---|
| 会議録からの抽出可否（上程・質疑・討論・採決） | **可能**。議事日程に `日程第○　議案第４１号　…　〔議案質疑・委員会付託・討論・採決〕` と取扱いが明記され、本文でも `△日程第○` → 「これより、議案質疑に入ります」→「これより、委員会付託に入ります」→「これより、討論に入ります」→「これより、採決に入ります」→「よって、本案は、承認することに決しました」と定型文で進む |
| 町HPに議決結果一覧があるか | **ある**。遠賀町公式サイト「審議案件・結果」 https://www.town.onga.lg.jp/site/gikai/list20-65.html （年別ページ、例: 令和8年 https://www.town.onga.lg.jp/site/gikai/81800.html ） |
| 形式（HTML / PDF） | **PDF のみ**。会議ごとに1ファイル（例: 令和8年6月定例会 = `/uploaded/attachment/12185.pdf`、125KB、1ページ）。**テキストレイヤあり**（埋め込みMS明朝/ゴシック）で、pypdf 相当で問題なく抽出できた |
| 個人別賛否の公表有無 | **公表されていない** |

### PDFの中身（`13_shingi_kekka_r08_06.pdf` より）

列は `議案番号 / 件名 / 議決年月日 / 議決結果` の4つだけ。

```
議案第４１号  専決処分の承認を求めることについて（専決第７号）遠賀町税条例の一部改正について  8.6.8   承 認
議案第４３号  遠賀町農業委員会委員の任命について                                    8.6.8   同 意
議案第４４号  遠賀町町道路線の認定について                                        8.6.15  原案可決
発議第１号    議員派遣の件について                                              8.6.15  原案可決
```

- 議決年月日は `8.6.15`（和暦.月.日）形式。
- 議決結果の語彙: `承 認` / `同 意` / `原案可決`（全角スペース入りの表記ゆれに注意）。
- **議案番号は会議録本文と完全に一致する**ので、`議案第○○号` をキーに会議録と突き合わせられる。

### 個人別賛否について（重要）

**会議録にも「審議案件・結果」PDFにも、議員個人の賛否は載っていない。**

- 会議録の起立採決は `───　賛成者起立　───　　１１：１〔１３〕`（賛成:反対〔出席数〕）という**人数だけ**。誰が起立したかは書かれていない。
- 異議なし採決は `───　異議なしの声　───` で人数すら出ない。
- PDFは会議全体としての議決結果のみ。

→ CLAUDE.md の絶対ルール「議員個人の賛否を推測して表示しない」に従い、**本プロジェクトでは個人別賛否を一切扱わない**。表示するのは「議案ごとの議決結果」と、起立採決の場合の「賛否の人数」までとする。

## 4. 分量とコストの見積もり

### 日程数

| 項目 | 結果 | 根拠 |

| 定例会の総日程数（平成17年〜令和8年6月） | **375日程**（実測） | 全期間一覧の「375件の日程がヒットしました」（`03_list_teireikai_all.html`） |
| 臨時会の総日程数 | **約85日程（推定）** | FINOは定例会・臨時会を通した連番。令和8年6月15日が `FINO=460` なので、460 − 375 ≒ 85。**P1で実測して差し替えること** |
| 全日程数 | **約460日程** | 同上 |
| 会議数（令和元年〜、2019年5月〜2026年6月 = 7.13年） | **約155日程**（うち定例会 約125） | 下記の按分 |
| 会議数（平成17年〜平成31年4月 = 14.33年） | **約305日程**（うち定例会 約250） | 下記の按分 |

按分の方法: 収録期間は2005年1月〜2026年6月の約21.5年で460日程 → 年あたり約21.4日程。実測の平成18年（定例会17日程／年、4定例会）とも整合する。
定例会の回次は臨時会と**通し番号を共有**している（令和8年: 第1回1月臨時会・第2回3月定例会・第3回6月定例会・第4回8月臨時会・第5回9月定例会）ので、「第○回」から定例会だけを数えることはできない。

料金は 2026-06-24 時点の公式価格（Claude API 第一者料金）。**Batch API は50%割引**。

前提と注意:

- **1日程 = 1リクエスト**で要約する前提。一般質問ごと・議案ごとに分けて要約すると、同じ日の本文を複数回送ることになり入力トークンが2〜4倍に増える。要約の粒度は P4 で決める設計判断。
- 出力は本文より圧倒的に短いので、費用はほぼ入力側で決まる。
- いずれにせよ**総額は二桁ドル以内**で、コストがこのプロジェクトの制約になることはない。モデルは費用ではなく**要約品質と誤りの少なさ**で選んでよい。

## 5. P0を終えての判断メモ

### P2（整形）のパーサ実装で難所になりそうなところ

1. **発言の分割は易しい。** `<A NAME="HUID\d+"></A>` で切って、行頭1文字（`○`/`◆`/`◎`/`△`）で種別を判定し、`肩書（氏名）` を切り出すだけ。HUIDが全会議通しのユニークIDなので、そのまま発言の主キーに使える。**ここは想定より大幅に楽。**
2. **難所は本文先頭のヘッダ部分**（出席者一覧・議事日程）。罫線素片で組んだアスキーアート表を解析する必要がある。3列×5行に分割された出欠表で、氏名は `仲　摩　靖　浩` のように全角スペース入り。**空白除去＋列幅による分割**を書くことになる。
3. **議案と議決結果の対応づけ。** 会議録では議案の上程日と採決日が別の日程にまたがる（例: 議案第４４号は6/8に質疑・委員会付託、6/15に採決）。議案単位のページを作るなら、**同一定例会内の複数日程をまたいで1議案の流れを組み立てる**必要がある。町HPのPDF（議決年月日つき）を併用すると突き合わせが楽になる。
4. **表記ゆれの正規化。** 全角/半角の算用数字（`日程第10` と `△日程第１０`）、`一　般　質　問` の字間スペース、`承 認` の語中スペース。正規化関数を1つ用意して全体で使い回す。
5. **年代分岐は不要。** 平成17年頃と令和で構造・記号・ラベルが同じだった。P6（平成分の追加）は**パーサの追加実装ではなく、単に取得対象を増やすだけ**で済む見込み。工数見積もりは大幅に下がる。
